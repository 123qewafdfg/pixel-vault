# B站登录与自动上传

本功能基于 v12 源码实现，本次构建为 v13 / 3.1-native，沿用现有签名。仅交付本地 APK，不发布线上版本、不生成任何增量补丁。

## 用户流程

1. 主页点击“B站登录”，用 B站客户端扫码并确认；同机使用可保存二维码后从相册扫描。
2. 进入嵌入，选择隐藏文件。已登录时，原文本入库按钮位置提供“将内容发放到 B站”。第一步点击“下一步”且实际隐藏文件合计不超过 45 MiB 时，会提示“你其实可以上传到哔站，确定吗？”；确定自动上传，选择“继续原流程”则进入手动承载图步骤。
3. 应用自动生成加密承载图、逐片上传、下载校验，全部通过后登记口令。
4. 直接进入水印图片步骤，可更换图片或使用默认图；点击“确定并嵌入”保存结果并展示口令。

首次进入本功能显示重点提示；未登录时保留原文本入库与手动流程。上传不会发布文章或动态。

## 数据与限制

- B站流程：实际待隐藏文件合计（智能压缩后的文件）和打包后载荷均不得超过 45 MiB。界面显示、按钮资格和上传检查共用同一统计口径；不使用压缩前原图大小，也不计入载体图或加密开销。
- 每张尾追加最多 6 MiB，包括密文、GCM 标签、元数据和 112 字节索引；使用最少张数并均衡分配。
- 5 MiB 一张，10/11 MiB 两张；恰好 12 MiB 会因协议开销使用三张，45 MiB 使用八张。
- 多片重复使用内置 `bili_carrier.png`，其原始大小为 2,747,567 字节。
- 载体 SHA-256：`d4a91ba66d89cdc9db228c7751dcecd7b8d773385a455bdc4e0e32a3d2d288cf`。
- 保留原手动流程的分片规则与后端 `tm-create` / `tm-get` 协议。
- Cookie 以 Android Keystore AES-GCM 加密，存放在 `noBackupFilesDir`，不发送至隐像后端。
- 下载文件大小与完整 SHA-256 必须匹配本地产物，不能用上传接口报告的本地哈希代替。
- 网络请求禁止自动重复上传；登记结果未确认时阻止当前页面重复提交。
- 取消会清理本次本地临时文件；远端已上传图片可能仍存在。

## 验证

执行 `:app:testDebugUnitTest :app:assembleDebug`。新增测试模拟上游，不上传真实图片，覆盖分片边界、原始字节、扫码状态、Cookie 域和有效期、恢复结果、删除尾部、相同大小的篡改、上传失败及取消。

真实验收仍需用户扫码并确认，验证单片、多片上传下载哈希、换图保存以及另一设备恢复。未完成真实验收前，不宣称 B站能稳定保留尾追加内容。
